# LifeQuest: Deterministic Event Order & Integration Architecture\n\n## 🔥 Critical Integration: Quest Completion Flow\n\nWhen user completes a quest, the **orchestrateQuestCompletion** function runs a deterministic 12-phase flow. This ensures all systems (XP, decay, recovery, notifications, native sync) work in correct order without race conditions.\n\n### PHASE ORDER (IMMUTABLE)\n\n```\nUser clicks \"Complete Quest\"\n  ↓\n[PHASE 1] XP CALCULATION\n  • baseXp = difficulty * 10\n  • multipliers: difficulty × streak × isDue × isChallenge\n  • apply daily cap (1000 XP/day max)\n  • RESULT: earnedXp (capped)\n  ↓\n[PHASE 2] SKILL ENGINE UPDATE\n  • call skillEngine.addXp(skillId, earnedXp, context)\n  • updates progressMap[skillId].mastery\n  • calculates nextDue via spaced repetition\n  • RESULT: skill.mastery updated\n  ↓\n[PHASE 3] DECAY SYSTEM CHECK (housekeeping)\n  • applyDecayToAllSkills(skillMap)\n  • applies Ebbinghaus forgetting curve\n  • returns updated skillMap + warnings\n  • RESULT: skills decayed if overdue\n  ↓\n[PHASE 4] LEVEL UP CHECK\n  • check if totalXp >= xpForLevel(level)\n  • calculate newLevel\n  • generate milestone rewards if level-up\n  • RESULT: leveledUp flag + newLevel\n  ↓\n[PHASE 5] STREAK & RECOVERY UPDATE\n  • calculate days since lastQuestCompletedAt\n  • if daysSinceLastQuest == 1: normal continuation (+1 streak)\n  • if daysSinceLastQuest > 1: check recovery state\n    - if streakFrozen: consume freeze token, keep streak\n    - else: reset streak to 1, apply comeback bonus\n  • RESULT: newStreak + streakMessage\n  ↓\n[PHASE 6] NOTIFICATION ELIGIBILITY CHECK\n  • for each skill: check canSendNotification(skillId)\n  • verify user hasn't seen 5+ similar notifications\n  • get adaptive frequency (based on ignore history)\n  • build content via buildNotificationContent()\n  • RESULT: notifications[] array\n  ↓\n[PHASE 7] WIDGET CACHE UPDATE\n  • updateWidgetCache with current focus skill + mastery\n  • update streak + streakRisk level\n  • update dailyProgress\n  • RESULT: widget data cached in localStorage\n  ↓\n[PHASE 8] STATE MUTATION (ATOMIC)\n  • UPDATE AppState:\n    - user.xp = newXp\n    - user.level = newLevel\n    - user.streak = newStreak\n    - user.lastQuestCompletedAt = now\n    - user.streakRiskLevel = calculated risk\n    - quest.completed = true\n  • RESULT: state fully updated\n  ↓\n[PHASE 9] NATIVE SYNC (Capacitor + Filesystem)\n  • TRY Capacitor.Preferences.set(lifequest_skills_v1, payload)\n  • TRY Capacitor.Filesystem.writeFile(lifequest_skills_v1.json)\n  • recordSync('preferences') + recordSync('filesystem')\n  • if either fails: log error, continue\n  • RESULT: skillMap synced to native, or graceful degradation\n  ↓\n[PHASE 10] ANALYTICS TRACKING\n  • trackEvent('quest_completed', properties)\n  • log: questId, skillId, xpEarned, streak, levelUp, difficulty\n  • RESULT: analytics recorded\n  ↓\n[PHASE 11] STATE VALIDATION\n  • validateQuestCompletionResult(prevState, newState, xpEarned)\n  • check invariants:\n    - XP increased correctly\n    - mastery in 0..100 range\n    - level increased if needed\n    - timestamp is recent\n  • if validation fails: attemptStateRecovery()\n  • RESULT: validation report + possible recovery\n  ↓\n[PHASE 12] SNAPSHOT FOR DEBUG\n  • capture stateSnapshot: { level, xp, streak, skills, widget, timestamp }\n  • return full QuestCompletionResult\n  • RESULT: completionResult stored in context\n  ↓\nDashboard renders QuestFeedbackDisplay\n  • shows XP earned\n  • shows level up if applicable\n  • shows notifications from phase 6\n  • shows warnings from phases 3, 9, 11\n  • auto-fades after 4 seconds\n```\n\n## 🔒 Critical State Integrity Checks\n\n### Invariants (Enforced by validateAppState):\n- `user.level: 1..100`\n- `user.xp: >= 0`\n- `user.streak: >= 0`\n- `skill.mastery: 0..100` for all skills\n- `skill.xp: >= 0` for all skills\n- `lastQuestCompletedAt <= now` (no future timestamps)\n- No expired tokens in recoveryState\n- No quest with future plannedDate if completed\n\n### Recovery (If Invariants Violated):\n1. `validateAppState()` returns errors\n2. `attemptStateRecovery(state)` clamps values:\n   - level ← Math.min(100, Math.max(1, level))\n   - xp ← Math.max(0, xp)\n   - mastery ← Math.min(100, Math.max(0, mastery))\n   - future timestamps ← now\n   - expired tokens removed\n3. Recovered state replaces current state\n4. Dev console logs all fixes\n\n## 🔀 Multi-System Interactions\n\n### Recovery System + Streak\n- When days since quest > 1:\n  - If `recoveryState.streakFrozen == true`:\n    - Consume freeze token\n    - Keep streak intact\n    - No XP penalty\n  - Else:\n    - Reset streak to 1\n    - Apply comeback bonus: 25% + (daysInactive * 10%) XP\n    - Trigger \"comeback mode\" notification\n\n### Decay System + Notification Frequency\n- When skill mastery drops due to inactivity:\n  -
